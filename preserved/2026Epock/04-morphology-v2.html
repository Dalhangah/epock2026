웹툰 캐릭터 조형 문법 학습 전략 v2.0

작가의 선뿐 아니라 형태 설계 규칙을 학습하기 위한 데이터 스키마

이 문서는 대화에서 논의한 설계안과 후속 검증 내용을 재구성한 기록입니다. 초기 가정과 실제 확인된 사실을 구분하며, 구현·라이선스는 추가 검증이 필요합니다.

01. 설계 목표

작가의 스타일을 단순한 선·색채가 아닌 등신비, 머리 형상, 상체·하체 폭 분포, 사지 단순화, 관절 표현, 포즈와 카메라까지 포함하는 조건부 조형 문법으로 기술한다.

02. 독립 조형 축

G1 신체 비율(head_ratio, arm_length_ratio, leg_length_ratio), G2 형태 언어(head_shape, curvature, asymmetry), G3 해부학적 추상화(hand_detail, joint_simplification), G4 체형·연령, G5 동작·시점. 범주형 태그와 연속 수치형 파라미터를 병행한다.

03. 머리 형태 확장

round, oval, square, trapezoid, triangle, heart, star, diamond, cloud, bean, custom 등 개방형 분류를 사용한다. shape_id만으로 부족하므로 폭/높이, 곡률, 돌출부 수, 대칭성, 깊이 프로파일을 함께 기록한다.

04. 상하체 H/D/A/V/S

상체와 하체를 독립적으로 H(직선), D(볼록), A(아래로 확장), V(아래로 수축), S(굴곡)로 정의해 5×5=25개 기본 조합을 만든다. 예: upper=A, lower=V는 복부·골반이 넓고 말단으로 좁아지는 형태. 실제 연결부의 연속성·관절 안전성은 메시에서 검증한다.

05. 학습 메타데이터

asset_id, species, body_plan, head_ratio, head_shape, upper_shape, lower_shape, shoulder/waist/hip widths, limb ratios, joint_simplification, pose_id, view, camera, render_style, source_provenance를 기록한다. 같은 자산의 정면·측면·후면은 동일 asset_id로 묶는다.

06. 조건부 생성과 검증

JSON 태그만 저장해도 모델이 자동으로 조형을 이해하는 것은 아니다. 조건 인코더·학습 손실·조합별 데이터 균형을 설계하고, 학습하지 않은 조합을 생성하는 일반화 테스트가 필요하다. Shape Key로 유지 가능한 변형과 새 토폴로지가 필요한 별·하트형 머리를 구분한다.
