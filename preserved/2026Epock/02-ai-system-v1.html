AI 학습 시스템 개발 설계서 v1.0

Colab 기반 A/B 이중 학습 파이프라인

이 문서는 대화에서 논의한 설계안과 후속 검증 내용을 재구성한 기록입니다. 초기 가정과 실제 확인된 사실을 구분하며, 구현·라이선스는 추가 검증이 필요합니다.

01. A/B 모델 구조

A는 무작위 초기화된 소형 Pixel-space DDPM/U-Net으로 64×64 MVP에서 시작해 128×128·256×256 확장을 검토한다. B는 SD 1.5 사전학습 모델을 기반으로 512×512 LoRA 추가 학습을 먼저 검증한다. LoRA와 전체 가중치 CPT는 동일하지 않다.

02. 데이터 파이프라인

Blender 자체 제작 원본 → 렌더링 RGB/실루엣/깊이·메타데이터 → 자산 단위 학습·검증 분리 → 모델별 전처리 → 학습 → 고정 시드 추론 → Epoch Archive → 웹툰 엔진으로 연결한다.

03. MVP 실험

A: 작은 자체 제작 3등신 인체 데이터셋, 64px, 제한된 step 학습, 주기적 체크포인트. B: 동일 원천 자산의 512px 렌더를 사용한 LoRA smoke test. 공통으로 프롬프트·시드·모델 버전·GPU·라이브러리 버전·실행 시간을 기록한다.

04. GPU와 실행 환경

Google Colab의 GPU 종류·세션 시간은 보장되지 않는다. T4급 16GB 환경에서 최소 실험을 먼저 실행하고, 메모리·시간 측정 후 L4/A10/A100 등 확장을 판단한다. Python, PyTorch, Diffusers, Accelerate, PEFT, Pillow, OpenCV, pandas, Blender, Git을 기본 도구로 검토한다.

05. Epoch와 서사의 분리

작품에서 1 Epoch를 1개월로 해석하되 실제 Epoch는 전체 학습 데이터 1회 순회를 뜻한다. 데이터셋 규모와 모델 구조가 다른 A/B의 Epoch 수는 학습 효율의 직접 비교 지표가 아니다. Loss, 생성 품질, 데이터 노출량, 연산량 등을 함께 기록한다.

06. 저장 및 재현성

학습 재시작 가능한 체크포인트(가중치·optimizer·scheduler·step·RNG 상태), 고정 시드 샘플, metrics.csv, config.json, 데이터셋 해시를 보존한다. 과적합과 모델 붕괴를 혼동하지 않고 정량·정성 평가를 병행한다.
