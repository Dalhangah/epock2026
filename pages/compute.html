왜 Colab을 선택했을까?

짧은 실험은 가볍게,
본학습은 A100을 우선 후보로.

연구자 선택 이유가속기 추천 · 실측 전

이 기록은 개발 환경을 선택한 이유와 다음 실험의 하드웨어 제안입니다. GPU 배정·학습 완료·성능 향상을 확인한 결과가 아닙니다.

01Colab을 개발 도구로 선택한 이유기록

작가는 “24시간 구동 후 반납하는 방식이라 비교적 A100 대여가 쉽게 승인된다”는 판단을 Colab 선택 이유로 설명했습니다. 장기간 장비를 확보하기보다 필요한 학습 작업을 세션 단위로 진행하려는 선택입니다.

위 설명은 작가의 선택 배경입니다. 24시간 뒤 반납하면 A100 승인 가능성이 높아진다는 Google의 보장 정책으로 확인된 것은 아닙니다.

Google 공식 안내에서 Colab Pro+는 충분한 컴퓨팅 단위가 있을 때 최대 24시간 연속 코드 실행을 지원합니다. 하드웨어 배정과 자원 한도는 변동되며, 컴퓨팅 단위 소진이나 실행 종료 등에 따라 중단될 수 있습니다. 따라서 24시간 사용과 A100 재배정을 보장받는 전용 서버 계약과는 다릅니다. Colab 공식 FAQ ↗

02현재 화면에서 확인한 선택지기록

2026.11.10 사용자가 제공한 화면에는 CPU, H100 GPU, G4 GPU, A100 GPU, L4 GPU, T4 GPU, v6e-1 TPU, v5e-1 TPU가 표시되었습니다. 당시 선택된 항목은 CPU입니다. 메뉴에 표시되는 것과 실제로 배정되는 것은 다릅니다.

실제 장치명·VRAM·시간당 컴퓨팅 단위 사용량은 실행 환경 연결 후 확인해야 합니다. 고용량 RAM은 시스템 메모리 설정이며 GPU VRAM을 늘리는 기능이 아닙니다.

03작업에 맞춰 고르는 기준기록

A100 · 본학습의 우선 후보

현재 검토하는 PyTorch·Diffusers 기반 Tiny 실험과 SD 1.5 캐릭터 LoRA 학습에 공통으로 사용할 우선 후보입니다. 학습용 연산 성능과 메모리 여유를 활용해 반복 실험 시간을 줄이는 방향입니다. 다만 작은 모델에서는 데이터 읽기나 코드 처리 시간이 병목이 될 수 있어, A100이 항상 가장 경제적이라고 단정하지 않습니다.

L4 또는 T4 · 작은 실험과 오류 확인

낮은 해상도의 선·도형 Tiny 모델, 데이터 로딩, 학습·저장·재개 검증부터 시작할 후보입니다. SD 1.5 LoRA도 배치 크기·정밀도·메모리 절약 설정에 따라 검토할 수 있습니다. 실제 메모리 사용량과 단위 소모량을 보고 A100 전환 여부를 결정합니다.

H100 또는 G4 · 필요가 확인된 뒤 비교

더 높은 사양의 선택지라고 작은 실험에서 이익이 자동으로 커지지는 않습니다. 학습 시간이 실제 병목일 때 같은 설정으로 처리량과 컴퓨팅 단위 소모를 비교합니다. G4는 기존 라이브러리와 연산 커널 호환도 먼저 확인합니다. 이 프로젝트에서의 성능·비용 우위는 아직 측정하지 않았습니다.

CPU · GPU가 필요 없는 준비 작업

이미지 분리, 파일·JSON 검사, 간단한 선·도형 데이터 생성에는 먼저 CPU를 사용합니다. 학습용 GPU를 문서 정리나 대기 시간에 계속 점유할 필요는 없습니다.

TPU · 현재는 우선순위에서 제외

기존 초안과 예정 작업이 CUDA GPU 중심인 만큼 TPU로 옮기는 추가 개발·검증 부담을 지금 늘리지 않는 제안입니다. TPU가 본질적으로 부적합하다는 뜻은 아닙니다.

가속기가 더 빠르다고 같은 학습 설정의 결과 품질이 자동으로 좋아지는 것은 아닙니다. 이 추천은 하드웨어 배정이나 실험 실행을 대신하지 않습니다.

0424시간 세션에 의존하지 않는 실험 기록기록
  1. 연결 직후 실제 GPU·VRAM, Python·PyTorch·CUDA·Diffusers 버전, 런타임 버전을 기록합니다.
  2. 짧은 준비 실행 후 같은 조건의 학습 스텝 시간·최대 VRAM·컴퓨팅 단위 소모를 측정합니다. 작은 시험의 속도를 전체 학습 시간 보장으로 해석하지 않습니다.
  3. 체크포인트에는 모델뿐 아니라 optimizer, scheduler, epoch/step, 난수 상태와 학습 설정을 저장합니다. Drive 등에 정기 보관하고 새 세션에서 재개를 시험합니다.
  4. 입출력 병목을 줄이기 위해 필요한 데이터는 실행 환경에 복사해 읽고, 결과는 지속 저장소에 보존합니다. 런타임 종료 시 로컬 파일은 사라질 수 있습니다.
  5. 두 모델 비교에서는 장치·정밀도·배치·총 학습 스텝·본 이미지 수를 기록합니다. GPU가 다르면 단순 학습 시간으로 모델 우열을 판단하지 않습니다.

런타임 버전은 호환성 검사를 통과한 환경으로 고정·기록하는 것이 제안입니다. 현재 화면의 ‘최신 버전’ 또는 ‘2026.10’ 중 어느 쪽이 기존 노트북에 적합한지는 아직 검증하지 않았습니다.

05근거와 확인 범위기록
  • 2026.11.10 작가의 Colab 선택 이유와 제공된 설정 화면. 스크린샷 자체는 이 페이지에 재게시하지 않았습니다.
  • Google Colab 공식 FAQ: 실행 시간·가용성·시스템 메모리·자원 사용 원칙.
  • Google Cloud GPU 문서: GPU 계열 및 혼합 정밀도 지원에 대한 일반 기술 근거. Colab의 실제 할당 사양·요금표로 대체하지 않습니다.
  • Diffusers LoRA 학습 문서: 적은 수의 추가 가중치를 학습하는 방식과 메모리 절약 특성.

이번 기록에서는 실제 GPU를 배정하거나 학습을 실행하지 않았습니다. 계정의 컴퓨팅 단위 잔액·시간당 소비량·현재 배정 가능 여부도 확인하지 않았습니다.
