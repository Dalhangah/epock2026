이번에는 독립 스모크가 아니라, TinyUNet VR0.02 조건부 모델로 외부 직선 데이터를 1 epoch 학습했습니다. 검증 loss 계산, 4가지 조건의 이미지 저장, 체크포인트 읽기까지 확인했습니다. 다만 생성 이미지는 아직 색 잡음에 가까워, 선을 원하는 대로 그리는 성능이나 작품 제작 준비가 완료된 것은 아닙니다.

✓ 실제 사용한 데이터와 모델

  • 전체 선 데이터 1,640쌍의 파일 대응·분할 검사와 base_group_id 중복 0 확인

실제 생성 이미지 · 조건을 전달했지만 그림 품질은 아직 미달

  • 기본값: 중심 (0.5, 0.5), 0°, 원본 두께 4px.
  • 각도만 90°, 두께만 8px, 중심 X만 0.65로 바꾼 비교 요청을 각각 실행했습니다.
  • 각 요청은 동일 seed로 시작합니다. 조건별 차이를 비교하기 위한 실험 설계이지 조건 준수의 증거는 아닙니다.
  • 중심 X=0.65는 훈련 범위 약 0.459~0.567 밖이라는 경고가 남았습니다. 이 결과는 범위 밖 탐색으로 따로 봅니다.

이번에 진전된 것과 남은 것

VR0.41에서는 변환된 조건을 준비하고 호환 문제를 찾았습니다. VR0.51은 학습과 생성 모두에 원본 모델의 동일 조건 규칙을 연결했습니다. 전수 JSON 키 점검도 1,640개에 대해 수행했으며, 구도 안내선 200개의 seed 키 부재를 구분해 기록했습니다. 이것이 전체 이미지의 시각 품질 검수까지 뜻하지는 않습니다.

  • 학습·검증·저장·생성 사건이 실행 로그에 남았습니다. 코드에는 events.jsonl과 생성 요청·적용 조건·결과 JSON 기록이 포함됩니다.
  • 이번 저장본은 RUN_MODE=new입니다. 체크포인트를 읽을 수 있다는 것과 끊어진 Colab 세션에서 동일하게 이어 학습하는 것은 다릅니다.
  • 직선 이외의 곡선·2D 도형·인체·서사 기반 작품 생성은 이번 검증 범위가 아닙니다.
  • 다음 검수: 충분한 학습 관찰, 가는 선 보존, 같은 seed 조건별 결과 비교, 범위 밖 요청 처리, 실제 중단·재개와 출력 품질.

08VR0.41: 선 데이터의 조건 변환 확인과 호환성 점검● 부분 검증

내용 업데이트 · 2026-11-18 11:29 (한국시간) · 저장된 실행 출력 확인

외부 선 이미지와 JSON을 모델에 전달할 입력 형태로 변환하는 단계가 실행되었습니다. 한 배치에 이미지·클래스 ID·12차원 수치 조건을 묶고, 생성 요청도 같은 형태로 바꾸는 결과를 확인했습니다. 다만 조건을 받아 학습·생성하는 모델까지 연결된 성공은 아닙니다.

확인 파일: EPOCK_PIPELINE_VR0.41_Lines_Research.ipynb. 파일 내부 표제의 v0.4.0 및 이전 스모크 설명과 별개로, 6A·6B·6C와 마지막 학습 셀의 실제 저장 출력을 기준으로 기록합니다.

✓ 6A · 한 배치 입력 확인

  • image: [8, 1, 128, 128], float32, 범위 0~1
  • class_id: [8]
  • cond12: [8, 12]
  • 현재 활성 차원: 중심 X·Y, 각도의 cos·sin, 선 두께의 정규화 값
  • 요청·변환된 조건·미지원 항목을 나누어 기록

나머지 7차원이 0이라는 것은 12가지 속성을 모두 제어한다는 뜻이 아닙니다.

✓ 6B · 생성 요청 변환

직선(straight), 중심 (0.5, 0.5), 회전 45°, 원본 선 두께 4px 요청이 class_id 12와 cond12로 변환되었습니다.

[0.5, 0.5, 0.7071, 0.7071, 0.0078125, 0, 0, 0, 0, 0, 0, 0]

이번 요청의 unsupported_conditions는 빈 목록입니다. 이는 변환기에서 받아들였다는 의미이지 모델이 해당 그림을 생성했다는 의미가 아닙니다. 512→128 축소 기준 두께는 1px입니다.

✓ 6C · 호환되지 않는 지점 발견

현재 데이터의 13종 클래스 목록에서 straight는 ID 12입니다. 검사 셀에 선언된 VR0.02 기준 목록에서는 line이 ID 3이므로, straight→line 별칭을 적용해도 ID가 다릅니다. 나머지 12종은 이 검사 셀의 별칭표에 매핑이 없어 별도 확장 대상으로 표시되었습니다.

검사 결과는 “기존 조건 변환은 아직 수정하지 않음”입니다. 클래스 이름과 정수 ID뿐 아니라 12차원 각 항목의 의미까지 맞춰야 합니다. 이 셀은 선언된 목록을 비교했으며 실제 VR0.02 체크포인트를 불러와 호환성을 검증한 것은 아닙니다.

이번 실행에서 확인하지 않은 것

  • 마지막 학습 셀 출력은 SKIPPED: RUN_EPOCH_PILOT=False입니다. VR0.41에서 새로운 epoch 학습·검증 loss·생성 이미지를 확인한 것으로 기록하지 않습니다.
  • 남아 있는 SmokeNoiseNet은 클래스·cond12 입력을 받지 않는 독립 실험 모델입니다. 조건 변환 결과만으로 조건부 학습이 완성되지는 않습니다.
  • 원본군 분리는 여전히 GROUP CHECK PENDING입니다. “JSON 필드 전수 점검” 셀의 저장 출력은 30개 샘플(straight)에 대한 집계이므로 전체 JSON 검수 완료로 간주하지 않습니다.
  • 각도·선 두께·곡선 형태 제어, 조건 밖 입력 처리, 작품 품질과 정확한 이어 학습은 후속 검증 대상입니다.

평가와 아직 남은 확인

SmokeNoiseNet은 Tiny-UNet VR0.02와 별개의 무조건부 실험 모델입니다. JSON이 함께 반환되어도 클래스·각도·선 종류를 모델 입력으로 전달하지 않습니다. 생성 목표를 선택하는 화면만으로 조건 제어가 완성되는 것은 아닙니다.

  • 이미지는 아직 잡음 형태로, 의도한 선·구도 또는 작품용 이미지가 생성된 것으로 판단하지 않습니다.
  • 원본군 분리 검사는 GROUP CHECK PENDING입니다. 파일 ID가 다르다는 것과 변형 원본군까지 분리되었다는 것은 다릅니다.
  • 명시적인 이미지 디코딩 검사는 6개 샘플입니다. 전체 파일 품질 검수 완료로 확대 해석하지 않습니다.
  • 512→128 LANCZOS 축소에서 가는 선 보존 여부를 추가 검수해야 합니다.
  • 재로드 성공은 중단 시점부터 같은 데이터 순서·난수 상태로 이어 학습했다는 검증이 아닙니다.
  • 저장 시 Pillow 사용 방식의 폐기 예정 경고가 있었지만, 이 실행에서는 저장과 재로드가 완료되었습니다.

2026.11.16 코드 검토: 기존 VR0.02는 절차적 도형 생성 경로를 사용하며, 새 1,640쌍의 선 이미지·JSON을 직접 읽는 로더는 아직 연결되지 않았습니다. 조건 분류·해상도·원본군 분할·체크포인트 호환성을 확인한 별도 실행으로 검증해야 합니다.

위 문단은 11월 16일의 VR0.02 검토 기록입니다. 이후 v0.3 독립 시험에서 외부 선 PNG·JSON 로더 연결을 확인했습니다. 이 결과를 VR0.02 본체 통합 완료로 간주하지 않습니다.

  1. 이미지·JSON 짝과 메타데이터 검수.
  2. 외부 파일 로더, 이미지 크기·채널·정규화 확인.

  4. 장면군 기준 분할 후 작은 학습·저장·재개 시험.

기존 코드에는 클래스와 12차원 수치 조건이 있지만, 스타일·카메라·여러 물체의 관계를 새 JSON 그대로 받아들이지는 않습니다. 기존 도형 회전값을 카메라 각도로 바꾸어 읽지 않습니다. 조건 인코더와 모델 입력 변경을 확인한 뒤 실제 지원 범위를 기록합니다.

서사를 단어나 JSON으로 변환하는 것만으로 제어가 생기지 않습니다. 모델이 학습한 조건만 연결하고, 지원하지 않는 동작·시점은 미지원으로 표시합니다. 통합 자동 생성 실행은 아직 검증되지 않았습니다.
