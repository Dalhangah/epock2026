09 럭시(Luxy) · 3D 렌더 대신 작화 이미지로 LoRA 준비 ● 제작 방향 변경 · 데이터 준비 중

내용 업데이트 · 2026-11-21 09:31 KST

럭시의 외형을 SD 1.5 기반 캐릭터 LoRA로 학습하기 위해, 직접 그린 이미지 중심으로 학습데이터를 준비합니다. 캐릭터 LoRA라는 학습 방향은 유지합니다. 럭시 전체를 Blender로 모델링해 카툰 렌더를 대량 제작하려던 계획에서 바꾼 부분은 학습용 이미지를 만드는 방식입니다.

왜 바꿨나요?

3D 모델을 한 번 만들면 많은 장면을 뽑는 데 유리합니다. 하지만 작가의 선과 그림체를 렌더에 살리려면 인체 모델링과 카툰 렌더링을 별도로 연구해야 합니다. 이번에는 그 시간을 줄이고, 럭시의 외형과 작가의 표현이 잘 드러나는 그림을 먼저 확보합니다.

어떻게 준비하나요?

  1. 럭시의 턴어라운드를 기준으로 Clip Studio Paint의 3D 인체 데생 인형 체형을 조정합니다.
  2. 럭시의 성격에 맞는 일상 동작 5~10개를 포즈 참고로 준비합니다. 3D 인형은 작화 보조이며, 인형 화면이나 렌더를 그대로 학습 이미지로 쓰지 않습니다.
  3. 작가의 선화와 컬러링을 담은 고품질 작화 이미지 약 10장으로 시작할 계획입니다. 포즈 수와 학습 이미지 수는 별개의 계획이며, 10장이면 충분하다는 검증 결과는 아닙니다.

이번 변경의 범위

럭시 쪽 제작 방식만 바뀌었습니다. 티니의 학습데이터용 추가 동작과 검수·수정은 별도 작업으로 이어갑니다. 럭시는 자료 준비 단계이며, 학습은 아직 실행하지 않았습니다. 생성 품질도 아직 검증하지 않았습니다. 파이프라인의 JiT-mini A/B/C 직선 실험은 이 캐릭터 LoRA와 별개입니다.

내용 업데이트 · 2026-11-18 11:40 (한국시간) · 전달 ZIP·제작 목록·실제 미리보기 확인

같은 모양의 반복에서, 서로 다른 모양이 함께 놓인 장면으로.

원·정삼각형·정사각형 3종을 바탕으로 660 + 192 + 216 = 1,068쌍의 이미지·JSON을 준비했습니다. 모두 512 × 512의 2D 기본도형 재료이며, 외곽선과 검정 채움을 같은 장면의 두 스타일로 관리합니다. 전체 평면도형 종류나 입체도형이 완성된 것은 아닙니다.

제작 단계 추가 / 누계 실제 파일 ID
VR0.03 · 기본 배열 660 / 660쌍 000001~000776 중 660개
VR0.04 · 같은 도형의 무작위 배열 192 / 852쌍 000777~000968
VR0.05 · 서로 다른 도형의 혼합 배열 216 / 1,068쌍 000969~001184

01 · 기본 형태와 배열을 먼저 구분합니다

단독형과 대각·11자 평행열·격자·S·O·X·L·Z 배열, 크기 변화와 평면 도형판의 투시 투영을 비교합니다. 개수는 1·2·3·4·5·6·8·12개이며, 적은 개수로 의미 없는 구도를 만드는 조합은 제외했습니다.

실제 크기를 달리한 장면과 깊이에 따라 화면상 크기가 달라지는 투시 장면은 별도 조건입니다. 투시로 원이 타원처럼 보이더라도 원본 도형 클래스와 화면에 투영된 모양을 구분해 기록합니다. 투시가 있어도 3D 입체도형 데이터는 아닙니다.

02 · 정해진 구도 없이 같은 도형을 배치합니다

VR0.04는 같은 종류의 원·정사각형·정삼각형을 각각 무작위로 배치한 192쌍입니다. 위치·크기·회전을 바꾸되, 화면 밖·겹침·너무 작은 도형은 제외하는 제약이 있는 무작위 배열입니다. 이번 추가분은 직교 투영으로, 큰 도형이 가까이 있다는 뜻은 아닙니다.

03 · 서로 다른 두세 종류를 한 장면에 넣습니다

VR0.05는 원+정사각형, 원+정삼각형, 정사각형+정삼각형, 세 종류 모두의 혼합 장면 216쌍입니다. 2종 혼합은 2~12개 중 지정된 개수, 3종 혼합은 3~12개 중 지정된 개수로 만들고, 종류별 수량 차이는 최대 1개로 제한했습니다. 위치·크기·회전을 달리하되 직교 투영·비겹침 조건을 유지합니다.

세 미리보기는 각 제작본에 포함된 실제 데이터 이미지입니다. 웹용 WebP 사본만 게시했으며 원본 학습 PNG를 변경하지 않았습니다. 학습된 모델의 생성 결과나 새로 그린 설명 이미지가 아닙니다.

이미지·JSON·엑셀은 같은 ID로 연결합니다

  • 이미지와 JSON은 여섯 자리 이름으로 1:1 대응합니다. 마지막 ID 001184는 개수 1,184개를 뜻하지 않습니다. 초기 검수 과정에서 생긴 빈 번호 116개를 유지해 실제 합계는 1,068개입니다.
  • 학습 로더는 연속 번호를 추측하지 않고 splits/train.txt와 splits/val.txt의 목록을 읽어야 합니다.
  • VR0.04·VR0.05 ZIP은 추가 이미지·JSON만 포함합니다. 공통 Excel·CSV·splits는 각 단계의 누계 목록이며, 최신 VR0.05 목록은 1,068쌍을 가리킵니다.
  • Excel의 Samples는 이미지별, Objects는 개체별 행입니다. 같은 종류 값은 쉼표 목록으로, 개체 좌표·크기·각도는 sample_id + object_id로 JSON과 연결합니다.
  • Excel만으로 모든 투영 행렬·정점을 손실 없이 복원한다고 가정하지 않습니다. 향후 편집→JSON은 원본 JSON에서 허용 열만 갱신하고, 좌표·크기 변경 시 이미지를 다시 생성하는 방식으로 검증합니다.

제작 검수와 학습 성과를 구분합니다

세 전달 ZIP을 확인해 660·192·216쌍, 서로 겹치지 않는 ID와 PNG·JSON 대응을 재확인했습니다. 제작 검수 기록에는 기존 852쌍 보존, 픽셀 중복 없음, 장면 그룹의 train/val 교차 없음이 기록되어 있습니다. 같은 장면의 외곽선·채움은 같은 분할에 둡니다.

자동 검수와 대표 이미지 확인은 데이터 제작 품질 점검입니다. 128px 축소의 가독성, 기존 선 데이터와의 혼합 비율, 다중 객체 조건 인코딩, 모델의 개수·배열·형태 제어와 학습 성능은 아직 별도 시험이 필요합니다. 타원·직사각형·일반 삼각형·다각형·별·입체·인체까지 모두 준비되었다는 의미가 아닙니다.

검수와 학습은 별도

현재 Colab의 외부 이미지·JSON 로더와 조건 입력 연결은 검증 전입니다. 선 가이드를 배웠다고 실제 사물의 구도를 이해한다고 단정하지 않습니다.

이 항목은 당시 파일럿 기록입니다. 아래 이전 개수·규격은 최신 선 데이터나 인체 데이터의 사양이 아닙니다. 후속 검토에서 다양성·구도 보완 필요가 확인되었습니다.

움직임의 문제와 분리하여, 선·도형·입체의 형태와 배치를 먼저 살펴봅니다.

원·삼각형·T자와 구·원뿔·육면체 등 정지 형태를 Blender로 렌더링합니다. 형태의 위치·회전·크기·정렬·간격, 카메라 시점과 화면 구도를 나누어 기록하는 방향입니다.

표현 확인할 내용
실루엣 검정 채움으로 외곽과 겹침 확인

같은 구형 장면의 256px 중간 출력 4종. Blender 렌더이며 AI 학습 결과가 아닙니다. 해칭은 화면 좌표에 고정한 시험으로, 곡면 추종 최종안은 아닙니다. 전체 파일럿 승인 전입니다.

개수와 화면 크기는 따로 기록

화면에 보이는 도형 수로 원샷·투샷·쓰리샷 등을 구분합니다. 롱샷·클로즈업 같은 화면 점유 크기, 로우앵글·아이레벨·하이앵글 같은 카메라 높이와는 별도 항목입니다. 장면에 배치한 수와 실제 보이는 수도 대조합니다.

짧은 이름, 이미지와 JSON 한 쌍

images/000001.png ↔ JSON/000001.json처럼 같은 자료의 이름을 맞춥니다. 번호는 000001부터 여섯 자리로 고정하며, 스타일별 이미지마다 고유 번호를 사용합니다. 같은 장면의 여러 스타일은 JSON의 장면 식별자로 연결합니다.

현재 상태와 다음 확인

24개 장면 × 4개 스타일, 최대 96쌍의 소규모 파일럿을 제작·검수 중입니다. 평면 선 출력의 결함을 발견해 재렌더링하고 있으며, 전체 업로드 완료나 학습 투입 승인을 의미하지 않습니다.

  • 파일 누락·중복, 이미지/JSON 일대일 대응과 실제 출력 크기 확인.
  • 형태·스타일·카메라·보이는 개수·가림·잘림을 이미지와 대조.
  • 카메라의 실제 변환, 오브젝트 배치, 스크립트 버전과 재현 정보 확인.
  • 동일 장면의 스타일 변형이 학습/평가 양쪽에 섞이지 않도록 원본 장면군 기준 분리 설계.

파일럿은 생성·검수 흐름을 시험하는 자료입니다. 완성된 학습 세트나 모델 성능 결과가 아닙니다. JSON 기록과 모델의 실제 조건 입력 지원은 별도 검증합니다.

3등신·4등신 A타입의 기본 T자 자세로 96쌍의 PNG·JSON을 제작했습니다. 실루엣·외곽·카툰 명암·해칭 4종이며 Excel 목록도 함께 관리합니다. 픽셀 기준 고유 이미지는 84개로, 실루엣 중복 12개를 별도 표시합니다. 학습 완료나 동작 데이터 완성을 뜻하지 않습니다.

인체 파일명은 000011~000014처럼 마지막 자리에 스타일 번호 1~4를 두며, 다음 장면은 000021부터 시작합니다. 선 데이터 번호 규칙과 혼합하지 않습니다.

현재는 바닥에서 쪼그려 그리기, 웅크려 숨기듯 그리기, 엎드려 즐겁게 그리기, 턱을 괴고 지루하게 그리기를 시험합니다. 기존 샘플의 바닥·도구 접촉과 손 리깅 문제를 확인했으며, 수정 포즈는 승인 전입니다. 중심선·도형화 가이드는 외곽보다 가늘고 옅게, 가이드 없는 버전과 구분합니다.

작가의 3등신·4등신 A타입 기본형을 바탕으로, 팔꿈치·무릎과 손가락의 굽힘을 시험합니다. SEAM·SHARP 표시를 참고하되, 표시만으로 실제 관절 위치나 변형 품질이 보장되지는 않습니다.

  • 손: 연필 쥐기와 검지 터치를 시험했습니다. 관절 배치·마디 길이·엄지 접촉과 손가락 관통을 수정·검수 중입니다. 모든 손 포즈가 승인된 상태는 아닙니다.
  • 해칭: 작가가 제공한 손드로잉 패턴으로 사선+교차, 가로선+격자를 비교했습니다. 화면 고정 방식과 곡면을 따르는 방식의 차이를 확인했습니다.
  • 남은 문제: 굽힌 관절에서 해칭 간격과 두께가 늘어납니다. 자세별 표면 좌표 보정을 시험 중이며 완전 해결로 표시하지 않습니다.
  • 손 표현: 손바닥·손가락은 해칭에서 제외하고 외곽과 형태를 살리는 방향입니다. 손가락에 해칭이 남은 피드백이 있어 추가 수정 중입니다.

관절 주변 선 밀도와 손의 가독성을 확인한 중간 비교본입니다. 손가락 해칭 잔류 등 후속 수정 대상이 있으므로 완성본이 아닙니다.

이 움직임 검수와 정지 도형 파일럿은 분리하여 진행합니다. 기존 원본을 보존하고 시험 버전으로 확인합니다.

내용 업데이트 · 2026-11-16 00:47 (한국시간) · 변경 기록

선화와 입체는 한 단계 개선됐습니다. 카툰 명암은 다시 조정합니다.

2026.11.13에 공유된 정면 샘플 4장은 같은 자세의 표현 차이를 확인하는 소규모 시험입니다. Blender로 만든 학습용 이미지 후보이며, 학습된 AI의 생성 결과가 아닙니다.

개선된 부분

  • 선화에서 빠졌던 둥근 머리와 전신 윤곽이 연결되고, 사각형 조각선이 크게 줄었습니다.
  • 회색 입체는 처음의 백색에 묻힌 출력보다 머리·몸통·팔다리의 볼륨이 읽힙니다.
  • 검정 실루엣의 외곽과 팔을 든 자세는 유지됩니다.

다음 수정

  • 카툰은 매우 옅은 한 덩어리에 가까워 2~3단계의 명암 면 분할이 보이지 않습니다.
  • 입체는 아직 대비가 약합니다. 선화는 목 주변 중복선·미세 잔선과 축소 시 선 굵기를 점검합니다.
  • 다른 시점·자세와 실제 학습 입력 크기에서 다시 검수합니다.

현재 판정: 시각 비교 완료, 학습 투입 승인 전. 같은 구도처럼 보이는 것과 카메라·메시·프레임 기록이 실제 일치하는 것은 별도로 확인해야 합니다.

0411월 13일 표현·메타데이터 검토 기록이전 검토

내용 업데이트 · 2026-11-16 00:47 (한국시간) · 변경 기록

원래의 표현 계획 전체와 이번 렌더 시험의 4종은 같은 목록이 아닙니다. 이번에는 실루엣·외곽선·회색 입체·카툰 명암을 먼저 비교했습니다.

계획한 표현 이번 샘플과의 관계 남은 작업
실루엣 검정 채움으로 확인 다른 자세·시점의 가림과 잘림 검수
메인선 outline_features가 외곽·겹침선 후보에 해당 목·손·관절선 정리, 학습 크기에서 식별성 검수
메인선 + 가이드선 이번 4장에는 없음 중심선·관절선의 정의와 별도 출력
혼합 도형형 / 인체 도형화 이번 4장에는 없음 신체 부위별 도형 대응과 출력
동세선 이번 4장에는 없음 리그·기준점과 연결한 동작 흐름 표현
회색 입체·카툰 명암 별도 렌더 표현 시험 중 입체 대비 개선, 카툰 단계 명암 재출력

외곽선만으로 가이드선이나 동세선을 구현했다고 보지 않습니다. 표현 후보를 모두 만들더라도 첫 학습에 모두 섞을지는 별도 실험으로 결정합니다.

메타데이터 검수는 별도 진행

첨부 PNG 4장(768 × 768, RGB)과 Blender 작업 대화에 공유된 JSON 4개를 직접 확인했습니다. JSON에는 v0.3.1, 86번 프레임, 정면, 공통 렌더 그룹과 원본군 ID가 기록되어 있습니다. 이미지 크기와 스타일 분류는 대응하지만, 재현 기록은 수정·재검증이 필요합니다.

  • 우선 점검: 네 JSON 모두 카메라 월드 행렬은 항등행렬, 위치는 (0, 0, 0)이지만 회전 X는 약 90도로 기록됩니다. 실제 평가된 카메라 변환과 저장 시점을 대조해야 합니다.
  • review 항목은 모두 unreviewed입니다. 검수 완료로 표시하지 않습니다.
  • 원본 PNG와 JSON의 파일명·스타일·해시 연결 확인. 전달본의 (1) 접미사만으로 연결 오류를 단정하지 않기.
  • BODY_BASE_UNVERIFIED·POSE_CURRENT 등 임시 식별값을 실제 체형·포즈 기록과 대조하기.
  • 메시·프레임·카메라·렌더 설정 및 스크립트 버전, 표현별 동일 장면 연결 확인.
  • 원본군 단위 학습/평가 분할, 실제 로더 입력 크기·채널·조건 입력 지원 확인.

JSON에 정보가 적혀 있는 것과 모델이 그 정보를 학습 조건으로 받는 것은 다릅니다. 이번에는 JSON 내용까지 읽었지만, 원본 .blend 실행과 카메라 재현·학습 입력 연결을 검증한 것은 아닙니다.
