# 진행현황 태스크 정렬·시각 관리

적용 범위: `pages/stage-*.html` 7개 단계, 최상위 `details.task-accordion` 34개. 하위 기술 설명 details는 별도 태스크가 아니다.

## 고정값과 강조값을 분리
- 각 항목의 `id`는 기존 URL을 보존한다. `data-task-number`는 단계 안의 고정 식별 번호다. NEW/NEXT여도 번호를 항상 표시한다. 새 항목은 기존 번호를 재사용하지 않고 다음 번호를 받는다.
- `data-task-order`는 해당 단계에서의 기본 순서다. 새 항목을 중간에 넣어야 하면 10, 20 사이에 15처럼 배정한다. 번호와 순서는 분리되어 있으므로 기존 링크와 번호를 바꾸지 않는다.
- `<main data-new-task="항목id" data-next-task="항목id">`에 단계별 최신 항목과 다음 항목을 각각 최대 하나 지정한다. 빈 값이면 강조하지 않는다.
- 새 NEW를 지정하면 이전 NEW는 별도 수동 정리 없이 기본 order로 복귀한다. NEXT도 동일하다. 다른 단계로 옮기는 기능은 아니다. 항목은 원래 단계 페이지에 계속 속한다.
- 표시 순서: NEW → NEXT → 나머지 기본 order. 번호는 화면 순위를 뜻하지 않는다.
- `assets/task-order.js`가 CSS flex/order를 부여한다. 접근성을 위해 실행 시 DOM/키보드/스크린리더 순서도 같은 순서로 맞춘다. 저장된 HTML의 콘텐츠 블록을 물리적으로 이동할 필요 없다.
- JS 비활성 시에도 원본 HTML과 번호, 시각, native accordion은 읽을 수 있다. 강조·동적 정렬만 적용되지 않는다.
- 진행 중은 open 유지, 완료·대기는 기존 상태대로 유지한다. NEW를 설정했다고 실제 작업 상태를 완료로 바꾸지 않는다.

## 내용 업데이트 시각
- 의미: 해당 태스크의 웹 기록 내용이 변경된 시각. 실제 실험 수행시각/완료일과 다르다.
- 최초 도입의 34개 항목은 GitHub 파일 이력을 역추적해 현재 태스크의 텍스트·링크·이미지가 마지막으로 변경된 커밋 시각을 사용했다. 페이지 전체 스타일/메뉴 변경시각으로 덮어쓰지 않았다.
- 향후 해당 태스크 내용이나 상태를 고친 경우에만 `.task-updated time`을 실제 수정시각(+09:00)으로 갱신한다. 표시 `YYYY-MM-DD HH:mm (한국시간)`, 기계값 ISO8601. 확인 불가면 이를 명시한다.
- 가능하면 확정된 내용 커밋 링크로 변경 기록 링크를 갱신한다. 저장 순서상 아직 새 커밋 SHA를 모르면 이전 커밋 링크를 최신 변경 근거처럼 남기지 말고 링크를 제거한 뒤 확정 후 추가한다.
- NEW/NEXT 교체, 정렬, 색상 등 표시만 바꾸는 경우 기존 항목의 내용 업데이트 시각은 바꾸지 않는다. 현재 시각을 매 접속 시 자동 생성하지 않는다.

## 게시 전 점검
1. 단계 내 id/고정 번호 중복 없음. NEW/NEXT id가 존재하고 서로 다름.
2. 새 NEW로 변경하는 시험에서 이전 NEW의 기본 순서 복귀 확인.
3. 키보드 순서와 시각 순서 일치, 기존 hash 링크 이동 시 열린 상태 확인.
4. 숫자·내용·사진·링크·진행 상태 보존, 날짜의 근거 확인.
5. 원격 main 최신 상태를 확인하고 변경 충돌을 피한 뒤 게시. GitHub Pages 빌드와 실제 URL 확인.
