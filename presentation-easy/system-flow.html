연습 그림이 작품이 되기까지

EPOCK은 학습할 그림을 만들고, AI를 시험하고, 그 과정을 이야기와 웹툰으로 연결하는 프로젝트입니다. 아래 순서는 전체 설계입니다. 번호가 이어져 있다고 모든 과정이 이미 자동으로 작동하는 것은 아닙니다. 원문 흐름도는 2026년 11월 18일 오후 11시 34분 기준이며, 이후 VR0.54 기록과 구분합니다.

01. 연습할 그림을 만들어요

선과 평면도형, Blender 인체를 만듭니다. 포즈·카메라·표현 방식에 맞춘 이미지와 JSON 설명, 엑셀 목록을 함께 준비합니다. 자료 제작과 검수는 진행 중입니다.

02. 작가가 그림과 설명을 살펴봐요

김준태 작가 등의 검수로 몸의 형태, 관절, 손, 실루엣, 구도와 설명 정보가 맞는지 확인합니다. 승인 전 이미지는 확정 자료와 분리합니다. 틀린 부분은 고쳐 다시 봅니다.

03. 같은 자료 묶음에 버전을 붙여요

이미지와 JSON의 이름, 목록과 버전을 맞추고 연습용·평가용을 나눕니다. 같은 원본의 변형은 한쪽에만 둡니다. 선 자료에서 원본군 누출 0을 확인했습니다. 다른 자료도 각각 검사해야 합니다.

04. 두 가지 학습 길로 나누어요

A는 기존 가중치 없이 Tiny-UNet VR0.02를 학습합니다. 원문 기준 직선 20에폭 실행을 확인했고, 이후 선 가중치 실험이 이어졌습니다. 곡선·도형·인체는 별도 검증합니다. B는 기존 SD 1.5 캐릭터 LoRA 계획이며 실행 완료를 확인하지 않았습니다. A의 파일을 SD 파일로 바꾸는 길이 아닙니다.

05. 실험 기록과 저장 파일을 남겨요

실험 번호(run ID)로 자료, 코드, 설정, 배운 가중치, 생성 그림을 연결합니다. A에서 오차 기록·일부 TensorBoard 준비·주기 저장과 최저값 저장이 확인되었습니다. 저장 파일을 읽은 것과 실제 중단 뒤 같은 상태로 재개한 것은 다릅니다.

06. 수치와 그림을 함께 검사해요

오차 숫자만 보고 작품에 쓰지 않습니다. 선 모양, 요청 조건의 반영, 포즈, 강한 잡음에서의 복원 결과를 함께 봅니다. 부족하면 02의 검수, 03의 자료 정리, 04의 학습으로 돌아갑니다.

07. 학습 기록을 이야기의 재료로 써요

실제 관찰과 숫자는 사실 기록으로 남깁니다. 자매가 아바타를 만드는 과정의 감정과 이야기는 작가의 창작으로 구분합니다. 오차 숫자가 인물의 감정을 증명하지 않습니다. 1에폭은 작품 속 하루로 연결하는 기준입니다.

08. 이야기를 모델에 맞는 요청으로 바꿔요

인물·행동·감정 표현·포즈·카메라·스타일·배경을 정해진 조건으로 바꿉니다. 모델이 실제 배운 조건만 전달합니다. 미지원 조건은 보류합니다. 단어를 적는 것만으로 포즈 조절이 생기지 않으므로 조건을 연결하는 코드와 대응 학습이 필요합니다.

09. 그림을 만든 뒤 작가가 골라요

배경과 인물을 따로 생성합니다. 사용 모델과 체크포인트, 요청 JSON, seed와 결과를 연결해 기록합니다. 실패한 그림이 자동으로 작품에 올라가지 않게 합니다.

10. 시간축 SNS 웹툰으로 보여 줘요

배경·인물·효과음·말풍선을 겹쳐 한 컷을 만듭니다. 컷·말풍선 번호와 언어별 대사, 2120~2126년 시간축, 댓글·좋아요를 연결할 계획입니다. 현재 artwork 샘플과 실제 서비스 완성은 구분합니다.

11. 독자의 반응을 듣고 다음 개선을 정해요

작품 반응과 오류 신고를 나누어 기록합니다. 독자의 그림이나 댓글을 허락 없이 학습자료로 넣지 않습니다. 목적·동의·사용 권리·품질을 확인한 자료만 다음 버전 후보로 검토합니다.

인간 자매가 직접 나오는 전체 이야기, 실루엣 표현과 결말은 작가가 정합니다. 매 에폭마다 만드는 아바타 제작 초안과 섞지 않습니다. 큰 사건과 결말은 이번 범위에서 다음 프로젝트로 나눈 결정도 유지합니다.

웹 화면과 생성 서버는 역할이 달라요

맡는 곳 할 일
독자의 브라우저 작품·발표·아카이브를 읽고 댓글·좋아요 등 입력을 보냅니다.
PHP·CodeIgniter 4 웹서버 계정과 권한, 요청이 올바른지 확인하고 생성 요청과 진행 상태를 관리합니다.
별도 Python 이미지 생성 서버 검수된 모델을 불러와 이미지를 만들고 결과를 돌려줍니다.
Colab 등 학습 환경 모델을 배우게 하는 실험을 합니다. 웹호스팅에서 직접 학습하는 구조가 아닙니다.

이것은 최근 선택한 구성이지 배포 완료 보고가 아닙니다. 서버 사이 요청·응답 형식, 인증, 기다리는 제한시간, 재시도와 중복 방지, 실패 표시를 구현하고 시험해야 합니다. 향후 따라 그린 인체와 원본의 유사성 비교, 선 그림이나 상황 설명을 포즈·구도 요청으로 바꾸는 기능도 계획입니다. 비교 기준과 보정·설명 방식부터 검증합니다.

MLOps: AI 작업을 잃어버리지 않고 안전하게 이어가는 규칙

MLOps는 AI를 만들고 시험하여 서비스에 쓰고, 이후 상태까지 관리하는 방법입니다. 교육 문서의 모든 도구를 설치했다는 뜻이 아니라 이 프로젝트에 필요한 원칙을 골라 적용하는 것입니다.

  • 다시 해볼 수 있게 묶기: 데이터·코드·환경·설정·모델을 실험 번호로 연결합니다. Colab 임시 파일에만 의존하지 않습니다.
  • 검수 후 채택: 실험 모델과 작품용 승인 모델을 나누고 승인 기록을 남깁니다. 문제 발생 시 이전 검수 버전으로 돌아갈 수 있게 합니다.
  • 환경 분리: 학습, 이미지 생성, 웹서비스의 프로그램 환경을 각각 기록합니다. 같은 환경을 담는 컨테이너는 후보 수단이지 도입 완료가 아닙니다.
  • 운영도 관찰: 실패·생성 지연·들어오는 요청의 변화와 그림 품질을 기록합니다. 재학습은 자동으로 강행하지 않고 사람 승인과 새 버전 검수를 거칩니다.

현재 확인된 도구는 Colab·PyTorch·TensorBoard·JSON 기록입니다. 교육 예시인 MLflow·Airflow·Vertex AI·Kubernetes를 모두 도입하기로 한 것은 아닙니다. 교육 문서의 개인 정보나 실습 인증정보는 공개하지 않습니다.
